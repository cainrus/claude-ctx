## Docs from code

The README is a short page with links; the docs live in `docs/`. Whatever the code already holds as data is not
written by hand there but rendered between `<!-- gen:NAME -->` markers by `scripts/docs.ts`:

| block | source |
|---|---|
| `settings`, `handoff-settings` | <!--ref:SETTINGS-->[SETTINGS](../src/config.ts#L75)<!--/ref-->; defaults are what `/ctx:status` reports on an empty config |
| `status-lines` | <!--ref:STATUS_EXAMPLES-->[STATUS_EXAMPLES](../hooks/status.ts#L174)<!--/ref-->, printed by the real `format()` |
| `ledger-events` | <!--ref:LEDGER_EVENTS-->[LEDGER_EVENTS](../src/ledger.ts#L11)<!--/ref-->, the table the event type is derived from |
| `ref NAME` | the exported `NAME`: a link to its line and the first paragraph of its doc comment |

Inside a sentence `<!--ref:NAME--><!--/ref-->` renders the link alone; quoted in a code span or
a fence it stays text. A renamed or removed symbol, one declared in two files, a symbol without a
doc comment (for `gen:ref`) and a ref marker without its pair fail by name with the doc's
file:line; a moved symbol only makes the doc stale, and `node scripts/docs.ts` rewrites it.

`test/docs.test.ts` fails when a generated block is stale, when a setting `/ctx:status` reports is missing
from `SETTINGS` (or the other way round), and when a documented env variable does not drive its key. So a new
setting or event goes into the code's own table first, and the docs follow from `node scripts/docs.ts`.

The tests cover every policy branch and the branch order, the presence probes (macOS and each Linux one, with fake
commands, plus the real probe of the machine they run on), the away budget, the cap tuner, the oracle against fixture
transcripts, the report math, and an end-to-end run of the exact `hooks/hooks.json` commands through `bash` with a
temp state directory, a fake transcript and a presence override — no network, any OS.

- `test/fixtures/real-shapes.jsonl` carries the line shapes Claude Code really writes (compaction, API errors,
  `system` and `attachment` lines, junk roots, a torn tail) with invented content. It is generated by
  `make-real-shapes.ts`, and a test checks the two agree.
- `test/concurrency.test.ts` races eight processes on the ledger and on one session file.
- `test/plugin.test.ts` runs `claude plugin validate --strict` on the plugin and the marketplace when a `claude`
  binary is on `PATH` (or in `CLAUDE_BIN`) and is skipped otherwise; CI runs it on a pinned Claude Code.
